Develop and verify a small change.

Keep model-specific behavior in adapters, mathematical objectives in loss functions, and user-specific workflows in caller code. Write tests that can distinguish a plausible implementation error from correct behavior.

Use synthetic fixtures for software tests. A new loss needs an independent mathematical reference and mask/bin-edge checks. Changes to the loop need failure-state and recovery checks. Changes to a native adapter require relevant native-model checks in the maintainer's controlled runtime.

Published source files use an explicit allowlist. Update release-files.json and MANIFEST.in deliberately when adding a public file. Source archives also contain standard setuptools metadata. Run the audit in a clean source tree; --sdist checks the final archive, permits only the declared source and known metadata names, and compares source bytes. CI runs this check after building and tests an installed wheel. It does not download weights or hold model-server credentials.

Security and reporting

Factory modules and callbacks are trusted executable Python. Checkpoints disable pickle but are not a general sandbox for untrusted files. Report the version, runtime, minimal synthetic reproducer and traceback for a software issue; do not attach credentials, model weights or confidential inputs. Use a private maintainer contact for security-sensitive reports.

Before publishing, inspect the source tree, artifacts and intended public history. Preserve upstream notices and review dependency-specific terms. Model parameters must be acquired separately.

Independent research software. Project code: Apache-2.0. External runtimes, model parameters and outputs retain their own terms.
