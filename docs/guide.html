Use the tool without editing its source.

Configure, then run

A CLI factory is an importable module:function accepting a JSON dictionary and returning Run. Factories are trusted executable Python. The CLI does not create a sandbox.

PYTHONPATH=examples hallulab run af2:build --config examples/af2.config.json
python examples/make_af3_input.py --output example-input
PYTHONPATH=examples hallulab run af3:build --config examples/af3.config.json

Use the corresponding runtime's Python and CLI. First replace the parameter-directory placeholders in the configs. The AF3 preparation command writes only an artificial poly-alanine input and a synthetic mask; it does not run a predictor. Native JSON contains inline MSA/template data; external *Path references are rejected. Example schedules demonstrate the API and are not optimized design recipes.

Three explicit stages

examples/stages.py demonstrates a logits-to-soft ramp, a soft stage with a temperature ramp, and a hard straight-through stage. Change stage_steps and learning_rate in JSON, or write your own factory. No source edits are needed.

Choose AF3 atom inputs

atom_mode="hard" is the default. During optimization, AF3 prepares the native atom layout for the current winning amino acid at each design position.

Set atom_mode="soft" to let the same amino-acid probabilities drive the query and the reference atom encoder. The gradient flows through both. The example factory accepts the following keys alongside the existing AF3 settings.

{
  "atom_mode": "soft",
  "design_positions": [3, 8],
  "soft_atom_alphabets": ["FY", "IV"]
}

Positions are zero-based and each alphabet follows the listed position. The initial implementation enumerates the Cartesian product of these alphabets and supports up to 27 native layouts. Use the AF3 3.0.3 Soft Atom runtime with F32, XLA attention, highest matmul precision, and zero recycles. Supply unmodified canonical protein chains with explicit empty unpairedMsa, pairedMsa, and templates fields (use "", "", and []). The soft encoder needs complete native key windows for real atoms. The native query rows and profile are checked for each chain. Mutations that change chain entity assignments or other fixed native conditioning are rejected.

The token probabilities and the atom layout weights share the same log probabilities. Layout weights are accumulated in log space to avoid underflow from multiplying many small probabilities. Scoring and export use the same F32 precision for choosing residue identities. Alpha, temperature, and their ratio must be finite positive normal values in F32.

The example uses probability controls throughout optimization. With the Python API, use soft=1 and hard=0 for gradients. Use hard=1 and gradient=False to inspect the locked distogram. sequence_from_logits() selects the best permitted residue at each position. full_prediction() uses that locked sequence's native atomic layout for forward-only structure prediction.

Full-chain Soft Atom with native atomic inputs

Set atom_mode="soft_sampled" to optimize all 20 amino-acid identities at every design position. Omit design_positions to design the entire chain. Use the same query-only AF3 3.0.3 runtime and numerical settings as above, with one AF3 featurization seed and the native CCD.

{
  "atom_mode": "soft_sampled",
  "soft_atom_samples": 4
}

Each draw takes an entire sequence from the current softmax probabilities. AF3 generates its native reference atom types, coordinates, masks and packed attention windows for that sequence. Each draw uses the same soft token probabilities, and the objective is averaged across draws. The gradient is the sum of the direct soft-token derivative and a likelihood-ratio estimate for the probability of drawing each native atom layout. Both update the same logits. The likelihood-ratio estimator uses a leave-one-out baseline and requires at least two draws. Four draws are used by default. Increasing the draw count increases per-step AF3 work and can reduce sampling noise.

Pass a fresh model key at each optimization step. The same logits, controls and key reproduce the same discrete layout draws. Soft evaluation returns the mean loss and mean metrics. With prediction=True the prediction is that of the first layout. Its native dictionary includes sampled_layout_identities in the library's amino-acid order and sampled_layout_losses for all draws. Score a locked sequence with hard=1 and gradient=False to run only its own layout. Diffusion runs on the decoded sequence's native atomic input.

Custom objectives

The objective receives a Prediction and controls. Return a scalar or (scalar, scalar_metrics). Use JAX operations when gradients are needed. The explicit objective replaces hidden default model objectives; include every desired term yourself.

from hallucination_lab.losses import distribution, interval, weighted

objective = weighted({
    "shape": (1.0, distribution(target, pair_mask, edges=edges)),
    "range": (0.2, interval(other_mask, edges, lower=4.0, upper=12.0)),
})

Here target, masks and edges are caller-supplied arrays. This snippet describes composition, not a recommended target or weight combination. A named control can override the corresponding weight. Native outputs differ between backends.

Checkpoints and endpoint identity

hallulab run hallucination_lab.toy:build --max-steps 3
hallulab run hallucination_lab.toy:build --resume runs/toy/checkpoint.npz

Use a new output directory for an independent run; do not let concurrent processes share it. Resume checks the tool/runtime source identity, problem identity, stages and model metadata. Preserve the original environment to resume an old checkpoint.

The logged loss belongs to evaluated_logits, before the next update. The final state.logits must be scored explicitly when reporting its objective. best_logits is the best recorded evaluated point under its recorded controls; scores from different controls need not be comparable.

Steps, callbacks and exports

gradient_step supports Adam/SGD, clipping and a gradient transform. A custom step returns StepResult; step_fn can also map stage names to callables. Observers run after a committed step and can stop by returning False. See examples/customize.py for the extension syntax.

save_prediction exports requested tensors; write_fasta exports caller-supplied sequences. AF3 full_prediction returns native forward outputs and identity information for caller-controlled structural export. This package does not turn model confidence into experimental validation.

AF3 full-prediction kernel selection

full_prediction(...) defaults to local Tokamax autotuning on a cache miss. This avoids assuming that a generic kernel fits every GPU shared-memory limit. The first call can take longer. Record the device, runtime, shape and autotune setting when comparing outputs; kernel choice can affect floating-point rounding. Use autotune=False only with a qualified kernel configuration. This setting applies to forward-only structure prediction and does not enable diffusion backpropagation.
